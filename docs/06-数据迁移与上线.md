# 锦程 ERP Web 数据迁移与上线方案

## 1. 数据源盘点

优先获取管家婆/POS 的员工、门店、仓库、商品、SKU、IMEI、库存、供应商、客户、销售、采购、收付款、未结单据和历史流水导出。每类数据记录来源表、字段解释、总量、时间范围、唯一键、空值、重复和负责人。

## 2. 迁移分层

1. 原始层：只保存原始导出，不手工改文件。
2. 暂存层：标准化编码、日期、金额、手机号和枚举，生成错误清单。
3. 映射层：旧 ID 对应新内部 ID，保留 source_system 和 source_id。
4. 正式层：按主数据、期初库存、未结单据、历史摘要的顺序导入。
5. 对账层：生成迁移前后数量、金额、序列号和差异报告。

## 3. 建议迁移范围

- 必迁：在职员工、门店、仓库、有效商品/SKU、当前库存、在库序列号、供应商、未结采购/调拨/销售、应收应付。
- 建议迁：近 12-24 个月销售、采购、退换货和客户历史，以支持售后和经营分析。
- 可归档：更早且低频历史保留为只读文件或历史库，不阻塞首期上线。

## 4. 切换步骤

1. staging 完成两轮全量迁移与对账。
2. 提前冻结主数据变更窗口，通知门店并准备回退方案。
3. 营业结束后停止旧系统业务写入，保留只读。
4. 导出增量，完成最终导入和关键数字签字。
5. 新系统开放，首日安排销售、库管、财务和技术支持值守。
6. 连续每日对账；达到稳定门槛后再扩店。

## 5. 回退原则

若出现库存/资金严重不一致、全局不可用、关键权限失效或数据无法恢复，停止新单据，保全日志和数据库快照，按预案恢复旧系统只读基线或修复后重放。禁止在两个系统同时继续写同一库存，以免形成无法对账的分叉。
