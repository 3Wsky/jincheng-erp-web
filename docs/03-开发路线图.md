# 锦程 ERP Web 开发路线图

## 1. 推荐节奏

以下按 1 名产品/业务负责人、2 名全栈或前后端工程师、1 名测试/实施的稳定投入估算。目标是第 6-8 周形成单店可用试点，完整 V1 约 12-16 周。若只有 1 名开发者，应按 5-8 个月规划，不能用压缩测试和迁移来换表面进度。

| 阶段 | 周期 | 主要交付 | 退出条件 |
|---|---:|---|---|
| 0. 业务与数据确认 | 1 周 | 销售流程、权限矩阵、成本口径、旧系统导出样例、原型 | 关键未决项有签字结论 |
| 1. 工程与治理基础 | 1-2 周 | 登录、组织员工、RBAC、审计、环境、CI/CD、导入框架 | 权限反向测试和部署流水线通过 |
| 2. 货与采购主链路 | 3-4 周 | 商品/SKU、IMEI、库存、查货、个人库、调拨、采购、付款/到货 | 采购与调拨端到端 UAT 通过 |
| 3. 销售与客户闭环 | 2-3 周 | 销售、收款、扣库存、退换货、客户、业绩 | 销售/退换货/对账 UAT 通过 |
| 4. 待办、资金与报表 | 2 周 | 待办、业务资金、库存资金、日报、驾驶舱基础 | 核心数字可下钻并对账 |
| 5. 试点与迁移 | 2 周 | 数据迁移、培训、单店试点、缺陷修复、恢复演练 | 连续稳定运行、P0 全通过 |
| 6. 扩店与平台接入 | 2-4 周 | 全门店推广、企微/会员/视频/直播接入 | 同步幂等、对账和告警通过 |

## 2. 先上线什么

首个试点版本只承诺：登录与权限、商品/SKU/IMEI、查货、库存/个人库、调拨、采购/收货、基础销售和待办。短视频、直播、企微、会员、复杂报表不阻塞首店试点，除非销售流程强依赖其中某个平台。

## 3. 每个迭代的完成定义

- 需求、交互、API、数据迁移影响和验收用例同时评审。
- 代码合并前通过 lint、类型检查、单元测试和关键模块集成测试。
- 涉及库存/资金的功能必须有并发、幂等、失败回滚和审计测试。
- 每两周在 staging 用真实角色演示，不接受只展示设计稿或接口返回。
- 文档、监控、告警、培训和回滚方案属于功能的一部分。

## 4. 试点策略

1. 选择业务相对完整、负责人配合度高的一家门店。
2. 先导入商品、SKU、员工和静态资料，再在切换窗口导入库存与未结单据。
3. 试点初期可保留旧系统只读查询，但禁止两个系统同时修改同一库存。
4. 每日对账库存、销售、收款、调拨和采购差异；差异必须在次日营业前闭环。
5. 连续 7-14 天无 P0 数据问题后再按门店批次推广。

## 5. 开发建议

- 先做业务闭环和数据一致性，不先做大而全的老板大屏。
- 模块化单体优先；数据库事务最容易保证采购、销售、库存与资金的一致性。
- Web 首期即做手机可用的扫码流程，能显著推迟 APP 开发成本。
- 使用 OpenAPI 契约和共享类型，为后续 PC/APP/小程序留接口，不共享数据库。
- 所有导入先验证再提交；所有外部同步要幂等、可重放、可对账。
- 报表先从可追溯的业务事实表生成，避免手工维护第二套“报表数字”。
- 不直接在生产改数据；异常修复走受控脚本或修正单据并留审计。
- 每次上线只引入一个可控变化集，避免“大爆炸式”切换。
