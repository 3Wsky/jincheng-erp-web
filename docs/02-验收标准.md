# 锦程 ERP Web 验收标准

## 1. 验收原则

- 每条标准必须能演示、查询、对账或自动测试，不能只写“功能正常”。
- 验收以测试环境签字结果为准，关键主链路必须使用脱敏后的真实业务样本。
- P0 主链路任一失败、数据不一致、越权或无法恢复，均不得上线。
- 暂定容量基线：30 门店、500 员工、50 万序列号档案、300 万库存流水、20 万客户、100 并发用户；真实规模明确后按“当前规模至少 3 倍”修订。

## 2. 功能验收

| 编号 | 业务域 | 可验收标准 | 优先级 |
|---|---|---|---|
| AC-F-001 | 登录与账号 | 有效账号可登录；冻结/离职账号立即失效；连续失败触发限流或锁定；退出后会话不可复用 | P0 |
| AC-F-002 | 权限 | 六类首批角色按本人/本店/指定范围/全公司返回不同数据；成本、毛利、手机号等字段按策略脱敏；越权接口返回 403 并记审计 | P0 |
| AC-F-003 | 商品主档 | 可维护品牌、品类、型号、颜色、容量、SKU、条码和序列号规则；重复编码被阻止；停用商品不能进入新业务单据 | P0 |
| AC-F-004 | 快速查货 | 可按型号、SKU、条码、IMEI、SN 查询；结果显示位置、状态、责任人和按权限显示的成本/数量 | P0 |
| AC-F-005 | 单机追踪 | 任一 IMEI 能展示从采购收货至当前的仓库、责任人、单据、调拨、销售、退换/售后完整时间线 | P0 |
| AC-F-006 | 数量库存 | 数量商品按 SKU × 仓库维护库存；每次增减都有单据和流水；余额与流水汇总一致 | P0 |
| AC-F-007 | 个人库存 | 领用后从公共库转入个人库；员工只看本人，店长看本店；归还/转交需接收方确认 | P0 |
| AC-F-008 | 调拨握手 | 申请、发出确认、锁定、出库、在途、接收确认、入库、完成按顺序执行；未收货前目标正常库存不增加 | P0 |
| AC-F-009 | 调拨异常 | 拒收、取消、部分收货、少货、错货、串号和损坏可记录差异、责任人、处理结果；主单状态正确 | P0 |
| AC-F-010 | 采购 | 采购单自动汇总数量和金额，支持审批、部分/多次付款、部分/全部到货；供应商和成本可追溯 | P0 |
| AC-F-011 | 付款到货差异 | 采购 10 台、付 10 台、收 8 台时，系统显示部分到货、未到 2 台和对应差异金额，库存只增加 8 台 | P0 |
| AC-F-012 | 销售 | 一单多商品可开单；序列号在确认节点唯一扣减；收款、客户、员工和库存关联；重复提交不重复扣库存 | P0 |
| AC-F-013 | 退换货 | 原单可发起退货/换货；退款、库存状态、序列号和业绩冲回按确认口径执行，并保留原单链路 | P0 |
| AC-F-014 | 业务资金 | 收入、采购支出、费用、退款、应收、应付、已付未到、库存资金和毛利可按日/店/权限查询并与抽样单据对账 | P0 |
| AC-F-015 | 客户主档 | 手机号/企微/会员等外部身份可映射到统一 customer_id；重复客户可识别和受控合并，历史不丢失 | P1 |
| AC-F-016 | 回访与提醒 | 每次有效回访关联客户、员工、时间和标准结果；同日同人同客有效人数只计 1；到期自动进入待办 | P1 |
| AC-F-017 | 待办 | 调拨、收货、异常、回访、审批进入本人待办；处理待办会真实推进业务状态，而非仅标记已读 | P0 |
| AC-F-018 | 外部同步 | 同一外部事件重复推送不重复计数；失败可重试；可查看原始 ID、批次、时间、错误与最终处理状态 | P1 |
| AC-F-019 | 报表 | 日/周/月报可自动生成；销售、库存、资金和客户关键指标可下钻到来源单据；权限与明细一致 | P1 |
| AC-F-020 | 离职交接 | 未完成库存、客户、在途和待办未清零前不能正式离职；完成后账号冻结，历史责任链保留 | P1 |

## 3. 数据一致性验收

1. 同一 IMEI/SN 在任一时刻最多只能处于一个有效库存位置，重复入库、销售或调拨必须被数据库约束或事务锁阻止。
2. 任意 SKU/仓库余额必须能由已生效库存流水重算；抽样和全量对账差异均为 0。
3. 单据状态转换必须符合状态机；跳步、回退和越权转换被拒绝并记录原因。
4. 销售、退货、调拨、收货等写操作在数据库事务内完成；故障注入后不得出现“单据成功但库存未变”或反向情况。
5. 同一幂等键重复请求 10 次，只产生一次业务结果，返回同一结果或明确冲突。
6. 审批后单据不可被普通编辑覆盖；作废使用状态与冲销记录，历史前后值可查。
7. API 同步原始事实字段不可由普通用户修改；人工补充字段与平台事实字段分开保存。
8. 采购付款、到货、未到数量和差异金额计算通过边界用例：0、部分、多次、超收、错货、退款。

## 4. 权限与安全验收

- 对每个角色建立至少一套正向与反向权限自动测试，覆盖接口、导出、搜索、报表和批量操作。
- 未授权用户无法通过修改 URL、请求参数、导出任务或对象 ID 访问其他门店/员工数据。
- 密码只保存强哈希；生产全程 HTTPS；会话 Cookie 使用 HttpOnly、Secure 和合适的 SameSite 策略。
- 财务、管理员、老板等高权限账号启用二次验证或企业统一身份认证。
- 重要操作记录账号、员工、IP、设备/客户端、request_id、前后值和时间。
- 上线前完成依赖漏洞扫描、密钥扫描和 Web 安全测试；不得遗留严重/高危未处置问题。
- 生产密钥不进入 Git；备份、导出和附件按敏感级别加密和限制下载。

## 5. 性能验收

在暂定容量基线和 100 并发用户下：

- 精确 IMEI/SN/条码查询 P95 ≤ 500 ms。
- 型号/SKU/组合查货 P95 ≤ 1.5 s。
- 普通列表与详情接口 P95 ≤ 800 ms，关键写操作 P95 ≤ 1.2 s。
- 角色首页首屏可交互 P75 ≤ 2.5 s（公司实际网络条件下测量）。
- 日报和常用汇总 P95 ≤ 5 s；超过 5 s 的导出/报表必须转异步任务并显示进度。
- 1 万行标准导入在 10 分钟内完成并提供成功、失败和原因明细。
- 压测期间业务错误率 < 0.5%，不得出现库存重复、数据库死锁风暴或队列失控。

## 6. 可用性与兼容性验收

- 支持公司规定的 Chrome/Edge 当前及前两个主要版本；手机端支持主流 Android 浏览器与微信内置浏览器的目标版本。
- 1366×768 和 1920×1080 下表格、筛选、弹窗无水平遮挡；360/390 px 手机宽度下扫码、待办、找货、收货、回访可完成。
- 扫码枪键盘输入和手机摄像头扫描均可识别目标条码；连续扫码有明确成功/失败反馈和防重复机制。
- 表单离开前提示未保存；网络失败显示可恢复提示，不把失败伪装成成功。
- 关键页面空状态、加载状态、无权限、服务异常和数据冲突均有可理解提示。

## 7. 可靠性、备份与恢复验收

- 试点阶段月可用性目标 ≥ 99.5%，计划维护提前通知并单独统计。
- 数据库恢复点目标 RPO ≤ 15 分钟，恢复时间目标 RTO ≤ 2 小时。
- 每日自动全量备份，增量/WAL 至少每 15 分钟可恢复；备份异地、加密并有保留策略。
- 上线前在空环境完成一次整库恢复演练，随机抽查账号、采购、库存、调拨、销售、客户和审计数据。
- API、Worker、数据库、磁盘、队列、备份、外部同步失败有监控和告警；关键告警有负责人和处理时限。
- 发布失败能回滚应用版本；数据库破坏性变更采用兼容迁移和前向修复，不依赖不可验证的临时手工操作。

## 8. 迁移与对账验收

- 旧系统导出数据先进入暂存区，经过字段映射、类型校验、重复识别和错误清单后再入正式库。
- 员工、门店、商品、SKU、库存、IMEI、供应商、客户和期初余额分别出具迁移统计。
- 迁移后公司总库存、门店库存、序列号数量、库存成本、应收应付等关键数字与签字基线一致。
- 无法自动迁移的记录必须有错误原因、业务处理人和最终决策，不允许静默丢弃。
- 切换前至少完成一次全量演练和一次增量/停机窗口演练。

## 9. UAT 与上线门槛

必须由真实业务角色完成以下端到端场景：

1. 新商品/SKU 建档 → 采购 → 多次付款 → 部分扫码到货 → 差异处理。
2. 序列号入库 → 门店调拨 → 在途 → 接收扫码 → 查货与单机追踪。
3. 公共库领用 → 个人库 → 转交/归还 → 责任链查询。
4. 销售开单 → 收款 → 扣库存 → 毛利与员工业绩 → 日报。
5. 原销售单退货/换货 → 退款/补款 → 库存与业绩冲回。
6. 客户建档 → 回访 → 下次提醒 → 到店 → 销售关联。
7. 运营同步内容数据 → 企微/会员归属 → 获客与成交归因。
8. 越权访问、字段脱敏、审批额度和导出权限验证。
9. 员工离职前库存、客户、待办交接与账号冻结。
10. 生产模拟故障、备份恢复和发布回滚演练。

上线条件：P0 全通过；P1 通过率 ≥ 95% 且剩余项有书面风险接受与完成日期；无未解决的数据一致性、越权、严重安全或恢复问题。
