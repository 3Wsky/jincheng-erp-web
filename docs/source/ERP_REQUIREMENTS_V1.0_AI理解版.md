# ERP_REQUIREMENTS_V1.0

> 用途：供 AI / 开发 Agent / 产品 Agent / 数据库设计 Agent 直接读取。  
> 版本：V1.0  
> 日期：2026-08-10  
> 状态：需求母版；后续讨论应以“增量更新”为主，不应无故删除已确认要求。

## 0. 产品定义

```yaml
product_type: 公司内部ERP
industry: 手机数码/3C，多门店，多员工
not_generic_saas: true
reference_baseline: 管家婆进销存能力
core_goal: 在进销存基础上强化快速查货、序列号追踪、责任库存、握手调拨、采购到货确认、业务财务、员工经营管理、客户/私域增长、自动报表与权限治理
core_model: 人 × 货 × 钱 × 事 × 权
```

### 0.1 五个维度
- **人**：谁负责、谁做了什么、产生了什么经营结果。
- **货**：什么货、在哪里、成本多少、归谁负责、当前什么状态。
- **钱**：钱从哪里来、花到哪里去、还有多少未结。
- **事**：业务当前进行到哪一步、谁现在需要处理什么。
- **权**：谁能看、谁能操作、谁能确认/审批、能看多大数据范围。

### 0.2 底层连接器
1. **单据**：所有库存/资金/责任变化必须有业务凭证。
2. **流程**：跨角色业务由状态机和握手确认驱动。
3. **状态**：禁止用简单的完成/未完成替代真实业务状态。
4. **权限**：Role × Scope × Action × Field × Approval。
5. **日志**：关键动作永久留痕，可追溯操作人、时间、前后值、来源。

### 0.3 不可破坏的全局原则
- `SOURCE_OF_TRUTH`: API 能获取的数据以系统同步为准，员工不得手填覆盖。
- `DOCUMENT_DRIVEN`: 库存、资金、责任变化必须来自单据。
- `HANDSHAKE`: 重要跨角色业务必须上下游确认后才完成。
- `TRACEABILITY`: 重要历史记录不可由普通用户物理删除。
- `ACTION_AND_OUTCOME`: 员工绩效同时看动作和结果。
- `ROLE_BASED_UX`: 不同角色首页/入口不同，不要求所有人看到完整 ERP 菜单。
- `AUTOMATED_REPORTING`: 日/周/月经营汇总尽量自动生成。

## 1. 核心业务闭环

### 1.1 商品闭环
`采购 -> 付款 -> 到货 -> 入库 -> 门店库存 -> 个人库存 -> 调拨 -> 销售 -> 退货/售后/异常`

### 1.2 客户闭环
`内容曝光 -> 咨询 -> 企业微信 -> 小程序会员 -> 跟进/回访 -> 意向 -> 到店 -> 成交 -> 老客户`

### 1.3 员工闭环
`上班 -> 工作任务 -> 短视频/直播 -> 获客 -> 私域 -> 回访 -> 销售 -> 库存责任 -> 月度绩效`

## 2. 商品与库存（货）

### REQ-GOODS-001 商品主档
字段至少包括：品牌、品类、型号、颜色、容量/内存、product_id、sku_id、商品编码、条码、是否序列号管理、IMEI/SN规则、当前采购成本、历史采购成本、参考销售价、商品状态。

### REQ-GOODS-002 两种库存模式
1. **序列号商品**：手机、平板、手表等；一机一码。
2. **数量商品**：手机壳、数据线、普通配件；SKU × 仓库 × 数量。

### REQ-GOODS-003 单机档案
每个 serial_id / IMEI / SN 记录：sku、采购成本、采购来源、入库时间、当前门店、当前仓库/个人库、当前责任人、库存状态、库龄、历史流转、调拨、销售、退货、售后/异常。

### REQ-GOODS-004 库存层级
`公司 -> 门店 -> 仓库 -> 员工个人库`

员工领货后应从公共库转入个人库，个人库属于“责任库存”。

### REQ-GOODS-005 全局快速查货
可按型号、品牌、颜色、容量、SKU、商品编码、IMEI、SN 搜索。

返回信息根据权限可包含：门店、数量/有货状态、最新成本、库龄、责任人。

### REQ-GOODS-006 库存状态
至少支持：
- NORMAL 正常库存
- LOCKED 锁定
- IN_TRANSIT 在途
- PENDING_CONFIRM 待确认
- PERSONAL 个人库
- SOLD 已售
- AFTER_SALES 售后
- ABNORMAL 异常

### REQ-GOODS-007 调拨握手状态机
`申请 -> 发出方确认 -> 锁定 -> 出库 -> 在途 -> 接收方扫码/确认 -> 入库 -> 完成`

规则：接收方未确认前，目标门店不得增加正常库存。

### REQ-GOODS-008 调拨异常
支持：拒收、取消、部分收货、少货、发错型号、IMEI/SN 不符、串号、损坏、其他异常备注。

### REQ-GOODS-009 库存变化单据来源
库存增减必须来自销售单、调拨单、采购入库单、退货单、盘盈/盘亏单、报损单、借出/归还单、售后出入库单等。

## 3. 采购与业务财务（钱）

### REQ-FIN-001 定位
V1 做“业务财务 ERP”，不急于替代完整会计软件。

必须回答：今日收入、今日支出、采购、销售、应收、应付、毛利、已付未到货、库存资金占用。

### REQ-FIN-002 采购单
采购单/清单字段至少包括：供应商、商品/SKU、数量、采购单价、金额；自动计算总额。

### REQ-FIN-003 采购状态机
`草稿 -> 待审批 -> 待付款 -> 部分付款/已付款 -> 待到货 -> 部分到货 -> 全部到货 -> 完成`

### REQ-FIN-004 付款记录
记录是否付款、金额、时间、方式、收款方/供应商、对应采购单；支持部分付款、多次付款。

### REQ-FIN-005 财务-库管握手
- 财务确认“钱是否付”。
- 库管确认“实物是否到”。
- 采购 10 台、已付 10 台、只收 8 台，则状态=部分到货，自动计算未到数量 2 和差异金额。
- 库管收序列号商品应通过扫码/录入实际 IMEI/SN 完成。

### REQ-FIN-006 经营资金
至少统计：销售收入、采购支出、其他费用、退款、应收、应付、已付款未到货金额、库存资金占用、毛利（按权限）。

### REQ-FIN-007 库存资金与库龄
至少分析 30/60/90 天以上库存的数量和成本金额，回答“多少钱被哪些货压住”。

## 4. 员工经营管理（人）

### REQ-PEOPLE-001 员工档案
字段至少包括：employee_id、姓名、手机、工号、门店、部门、岗位、上级、入职时间、在职状态、ERP账号、角色、权限、外部平台身份映射。

### REQ-PEOPLE-002 考勤
员工本人：今日/月度出勤、迟到、早退、缺勤、请假/异常。  
店长：本店。  
人事：授权范围。

### REQ-PEOPLE-003 销售业绩
数据必须来自真实销售业务，自动生成：
- 日：销量、销售额、毛利
- 周：销量、销售额、毛利、排名
- 月：销量、销售额、毛利、目标完成率、排名

### REQ-PEOPLE-004 个人库存
员工查看自己名下：商品、IMEI/SN、库龄、来源、领取时间、待接收调拨、待交接、异常。

### REQ-PEOPLE-005 短视频月度任务
短视频是销售人员除销售业绩外的月度必做任务。  
任务状态：`待拍摄 -> 已拍摄 -> 待审核 -> 已发布 -> 数据回收`。

### REQ-PEOPLE-006 短视频 API
自动同步：员工/账号、作品ID、发布日期/时间、链接、播放、点赞、评论、收藏、分享及平台可提供指标。  
禁止员工手填覆盖这些事实数据。

### REQ-PEOPLE-007 短视频绩效
动作：拍摄数、审核数、发布数、任务完成率。  
结果：总播放、平均播放、咨询/线索、新增企微、新增会员、到店、成交、销售额。

### REQ-PEOPLE-008 直播任务
直播是销售人员月度经营任务。记录/同步：日期、账号、参与员工、开播/下播、有效时长、场观、咨询、新增企微、新增会员、到店、成交、销售额。

### REQ-PEOPLE-009 老客回访必须实名到客户
禁止只报“今日回访 10 人”。每个有效回访必须关联 customer_id。

回访记录：客户、所属销售、历史购买、时间、方式、执行员工、结果、意向、备注、下次回访时间。

### REQ-PEOPLE-010 回访结果枚举
`无需求 / 有意向 / 待报价 / 待到店 / 已成交 / 拒绝联系 / 号码无效 / 下次跟进`

若结果=有意向，建议要求：意向商品、预计购买时间、下次联系日期。

### REQ-PEOPLE-011 防刷回访
同一员工同一天对同一 customer_id 多次操作可以保留日志，但“有效回访人数”只计 1。  
有效回访至少必须有：真实客户、员工、时间、结果、业务记录。

### REQ-PEOPLE-012 跟进提醒
回访可设置 next_followup_at，到期自动进入“我的待办”。

### REQ-PEOPLE-013 员工360经营档案
必须能够聚合：
- 销售：销量/销售额/毛利/完成率/排名
- 内容：任务/发布/播放/获客/成交
- 直播：场次/时长/获客/到店/成交/销售额
- 客户：回访/有效沟通/意向/到店/成交/老客销售额
- 私域：企微新增/会员新增/私域成交
- 工作：出勤/迟到/个人库存/待办/异常

### REQ-PEOPLE-014 双层绩效
动作指标：出勤、视频数量、直播场次/时长、回访人数、企微新增、会员新增。  
结果指标：销量、销售额、毛利、视频获客、直播获客、老客成交、回访转化率、企微转化率、会员成交率、老客复购率。

## 5. 客户与私域

### REQ-CRM-001 统一 Customer ID
企业微信、小程序会员、ERP 客户、老客名单必须尽量统一到同一个 customer_id。

映射字段可能包含：手机号、企业微信 external_userid、小程序 member_id、OpenID/UnionID（按实际可获取/合规能力）、所属门店、所属销售、来源渠道。

### REQ-CRM-002 客户完整档案
基础资料、所属员工/门店、来源、首次接触、企微关系、小程序关系、历史购买、累计消费、最近购买、回访、当前意向、下次联系、售后、最近活跃。

### REQ-CRM-003 企业微信 API
自动同步实际 API 可获取的：客户ID、所属员工、添加时间、来源、标签、关系状态、新增、删除/流失、当前客户总量等。

### REQ-CRM-004 企业微信指标
员工维度：今日/本周/本月新增、累计客户；进一步关联有效客户、意向、到店、成交、成交金额。

### REQ-CRM-005 小程序 API
自动同步：member_id、注册时间、来源员工、来源门店、来源渠道、会员状态、后续消费行为。

建议：每员工专属会员二维码/邀请码，实现自动归属。

### REQ-CRM-006 会员指标
新增会员、活跃会员、消费会员、会员成交人数、会员成交金额。

### REQ-CRM-007 老客漏斗
`老客户池 -> 本月回访 -> 有效沟通 -> 产生意向 -> 到店 -> 成交 -> 老客销售额`

### REQ-CRM-008 全链路归因目标
尽可能追踪：`短视频 -> 咨询 -> 企业微信 -> 小程序会员 -> 跟进/回访 -> 到店 -> 销售单 -> 成交`。

最终可回答：某条视频/某账号/某员工/某渠道带来了多少客户和销售额。

## 6. 业务事件/待办（事）

### REQ-EVENT-001 我的待办
统一汇聚：
- 调拨待确认
- 采购待收货
- 采购/付款异常
- 库存异常
- 个人库存待交接
- 今日客户回访
- 到期跟进
- 考勤异常
- 权限/审批事项
- 其他业务异常

### REQ-EVENT-002 待办必须回写业务
完成待办必须改变对应 document/event 的真实状态，不能只是把提醒标记已读。

## 7. 权限（权）

### REQ-AUTH-001 权限模型
`Permission = Role × DataScope × Action × Field × Approval`

### REQ-AUTH-002 首批角色
- HR 人事
- FINANCE 财务
- WAREHOUSE 库管
- STORE_MANAGER 店长
- SALES 销售
- OPERATIONS 运营

可扩展：财务主管、高级销售、区域经理、管理员、老板/管理层。

### REQ-AUTH-003 RBAC
一人可多角色，例如：`店长 + 库管`。权限必须配置化，不硬编码岗位逻辑。

### REQ-AUTH-004 数据范围
至少支持：`本人 / 本门店 / 指定门店 / 指定区域 / 全公司`。

### REQ-AUTH-005 字段脱敏
示例：
- 销售：可只看到“有货/缺货”或数量，不看成本。
- 店长：看本店/授权范围库存和经营数据。
- 财务/老板：按权限看成本、毛利、库存资金。

### REQ-AUTH-006 销售端
首页重点：今日业绩、我的库存、找货、待处理调拨、老客回访、企微、会员、视频任务、直播任务。

### REQ-AUTH-007 店长端
看本店的人/货/钱：考勤、销售、库存、个人库、调拨、毛利、库龄、内容完成、客户经营。  
原则上不看其他门店敏感利润、工资、财务账户。

### REQ-AUTH-008 库管端
待收货采购单、待发调拨、在途、待确认入库、库存异常、今日入库、今日出库。

### REQ-AUTH-009 财务端
采购、付款、收款、应收、应付、已付款待到货、部分到货、未到货金额、库存资金占用。

### REQ-AUTH-010 人事端
员工档案、部门岗位、入职离职、考勤、排班/请假、账号、权限申请。  
人事权限不等于可以看采购底价、公司利润、公司账户等敏感财务数据。

### REQ-AUTH-011 运营端
“看得多、改得少”：销售趋势、门店/员工排名、视频、直播、企微、会员、客户转化、商品销量、库存周转、活动、日周月报。  
原则上禁止：修改库存、修改采购成本、删除销售单、确认付款、强制完成调拨。

### REQ-AUTH-012 离职交接
`发起离职 -> 检查库存/在途/未完成单据/待办/客户 -> 库存交接 -> 客户交接 -> 业务交接 -> 权限关闭 -> 账号冻结 -> 正式离职`

历史记录永久保留。

## 8. 数据接入中心 Integration Center

### REQ-INT-001 统一接入层
`短视频API / 企业微信API / 小程序API / 未来直播API / O2O / 其他系统 -> Integration Center -> ERP统一模型`

避免每个平台 API 直接耦合核心 ERP 业务代码。

### REQ-INT-002 员工身份映射
内部 employee_id 作为主键，映射企业微信 userid、短视频账号、直播账号、小程序推广员 ID 等。

### REQ-INT-003 数据治理
- API事实数据不可人工覆盖。
- 保存外部原始ID。
- 记录同步时间、状态、错误。
- 同步必须幂等，防重复计数。
- 平台字段变化优先在接入层适配。

## 9. 报表与老板驾驶舱

### REQ-REPORT-001 日报
今日销售、销量、毛利、采购、收入、支出、调拨、库存异常、考勤、视频发布、直播、企微新增、会员新增、老客回访。

### REQ-REPORT-002 周报
经营趋势、门店排行、员工排行、商品排行、库存变化、私域增长、内容表现、关键异常。

### REQ-REPORT-003 月报
公司经营、门店经营、员工经营、商品经营、客户经营、库存资金、内容运营、私域沉淀。

### REQ-REPORT-004 老板驾驶舱
- 人：出勤、销售排名、目标完成率、视频/直播、回访、私域增长。
- 货：库存、在途、调拨、库龄、滞销、异常。
- 钱：收入、支出、销售额、毛利、采购、应收应付、库存资金占用。
- 客户：新客、企微、会员、老客回访、意向、到店、成交。

## 10. 内部主数据 ID

```yaml
employee_id: 员工统一ID
product_id: 商品主档ID
sku_id: 商品规格ID
serial_id: 单台序列号商品ID，与IMEI/SN关联
customer_id: 客户统一ID
store_id: 门店ID
warehouse_id: 仓库/个人库ID
document_id: 业务单据ID
event_id: 业务事件/待办/异常ID
```

规则：外部平台 ID 作为映射，不作为 ERP 核心主键。

6. 调拨握手流程
7. 采购单/采购清单
8. 财务付款 + 库管到货确认
9. 销售业绩汇总
10. 短视频任务 + API
11. 直播任务
12. 老客户回访 + 提醒
13. 企业微信 API
14. 小程序会员 API
15. 统一客户主档
16. 收支/应收应付/库存资金
17. 待办/事件中心

### V1 暂不做重
- 完整会计科目
- 总账
- 会计凭证
- 资产负债表
- 极其复杂的工资系统
- 大型 OA 审批平台
- 与当前业务无关的传统重型 CRM 功能

## 12. 当前最高优先级未决问题：销售单

销售单是连接 `人 + 货 + 钱 + 客户` 的关键业务单据，下一步必须确认：

1. 销售单从哪里产生（管家婆/POS/ERP/其他）？
2. 谁开单？在哪个设备/系统开？
3. 什么时候扣库存？
4. IMEI/SN 在哪一步扫描/录入？
5. 谁确认收款？
6. 微信/支付宝/现金/银行卡如何记录？
7. 是否存在分期？
8. 是否存在以旧换新？
9. 优惠券如何处理？
10. 小程序订单如何关联？
11. 是否存在批发客户和批发价？
12. 退货/换货流程如何处理？
13. 一单多商品如何处理？
14. 一单多人参与时如何分配业绩？
15. 毛利口径是什么？
16. 旧系统历史销售/库存是否迁移或通过 API/导入同步？

---

## 13. 开发/AI执行约束

- 不得把“库存数量”与“库存状态”混为一谈；在途/待确认不算目标门店正常可售库存。
- 不得因某岗位拥有某模块菜单权限就默认可看所有字段；成本、利润、账户等必须独立字段权限。
- 不得通过员工手工填报替代已存在的 API 数据。
- 不得以“回访次数”替代“回访客户数”和“有效回访数”。
- 不得删除历史责任链；调拨、采购收货、个人库、离职交接都应保留参与人和时间。
- 不得在未确认销售业务源之前锁死销售单数据库结构；先保留扩展能力。
- 所有跨系统对象优先通过内部 ID + 外部映射表设计。
- 所有重要流程必须有状态机、操作日志、异常分支。

## 14. 验收视角

系统最终至少要能直接回答以下问题：

1. 某型号现在全公司哪里有货？具体哪几台？谁负责？成本多少（若有权限）？
2. 某一台 IMEI 从采购到现在经历了哪些人、哪些仓、哪些单据？
3. 某笔采购付了多少钱？实际到了多少？还有多少货未到？
4. 某员工今天/本周/本月卖了多少、拍了多少视频、直播多久、回访了谁、加了多少企微、拉了多少会员，最终产生多少成交？
5. 某员工名下还有哪些库存和待交接事项？
6. 某客户从哪里来的？属于谁？历史买过什么？最近谁联系过？下次什么时候跟？
7. 某条视频/某次直播是否带来了企微、会员、到店和成交？
8. 当前公司有多少钱压在 30/60/90 天库存里？
9. 今天有哪些采购、调拨、库存、回访、考勤异常必须处理？
10. 每个角色是否只能看到和操作自己应该看到/操作的数据？
