# 锦程 ERP Web 待确认问题

## A. 上线前阻塞项

1. 销售单目前从管家婆、POS、其他系统还是人工产生？未来由哪个系统作为唯一来源？
2. 谁开单、在哪个设备开、何时锁库存、何时真正扣库存？
3. IMEI/SN 在开单、出库还是收款时扫描？扫码失败如何处理？
4. 谁确认收款？微信、支付宝、现金、银行卡、分期、赊销如何记录和对账？
5. 是否存在以旧换新、优惠券、小程序订单、批发价和一单多人分业绩？
6. 退货、换货、补差价、退款、退回序列号和业绩冲回的实际流程是什么？
7. 毛利按单机实际成本还是其他成本口径？配件是否采用移动加权平均？
8. 旧管家婆能导出哪些表或是否有 API/数据库访问权限？请提供脱敏样例。

## B. 业务规模与基础资料

1. 公司、区域、门店、仓库、员工、账号的真实数量和未来两年增长预期。
2. SKU 数、序列号档案数、年销售单量、库存流水量、客户数和峰值并发。
3. 现有门店名称、编码、仓库层级、个人库使用规则和负库存政策。
4. 供应商、采购审批层级、付款额度、超收/少收容差和退货流程。
5. 盘点频率、盘盈盘亏审批、报损、借出、售后和样机管理规则。

## C. 权限与组织

1. 六类首批角色的人员名单，是否存在“店长 + 库管”等兼岗。
2. 各角色能看哪些门店、是否能看数量、成本、毛利、客户手机号和财务账户。
3. 哪些动作需要审批，按什么金额/数量分级，谁能撤回、作废或强制处理。
4. 离职交接的责任人、完成时限和可例外条件。
5. 是否需要企业微信扫码登录/单点登录及高权限二次验证。

## D. 外部平台

1. 企业微信主体、应用、客户联系 API 权限和现有 userid/external_userid 导出能力。
2. 小程序主体、member_id/OpenID/UnionID 获取能力、员工二维码/邀请码方案。
3. 短视频和直播平台名称、账号归属、开放平台权限、指标和历史数据范围。
4. 各平台数据保存、员工/客户授权和合规要求。
5. API 不可用时是否允许人工导入，哪些字段只能系统同步。

## E. 技术与上线

1. 生产部署在公司机房、国内云还是混合环境；域名、HTTPS、备案和远程访问要求。
2. 门店网络质量、是否需要 VPN、是否存在断网继续开单的硬性需求。
3. 扫码枪、标签打印机、小票打印机、摄像头、串口设备型号与驱动。
4. 谁负责系统管理员、数据库备份、故障响应、员工培训和权限审批。
5. 允许的停机切换窗口、旧系统并行/只读期限和回退条件。

## 建议的确认方式

安排 2 次各 90 分钟的业务工作坊：第一次只走销售、收款、库存和退换货真实案例；第二次走采购、调拨、权限、迁移和异常。会后用 10 个真实单据样本验证结论，并由销售、库管、财务、店长共同签字。
