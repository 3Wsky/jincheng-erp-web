## B. 业务规模与基础资料

1. 公司、区域、门店、仓库、员工、账号的真实数量和未来两年增长预期。
2. SKU 数、序列号档案数、年销售单量、库存流水量、客户数和峰值并发。
3. 现有门店名称、编码、仓库层级、个人库使用规则和负库存政策。
4. 供应商、采购审批层级、付款额度、超收/少收容差和退货流程。
5. 盘点频率、盘盈盘亏审批、报损、借出、售后和样机管理规则。

> 权限三维决策题见 [`20-业务签字决策清单.md`](20-业务签字决策清单.md) B 组；原问题保留供追溯。

1. 六类首批角色的人员名单，是否存在“店长 + 库管”等兼岗。（核心五岗已于 2026-08-12 业务确认，见 `11-角色权限矩阵.md` 第 1 节；兼岗叠加规则随 docs/20 DEC-PERM-01~03 一并签字）
2. 各角色能看哪些门店、是否能看数量、成本、毛利、客户手机号和财务账户。→ docs/20 DEC-PERM-01（数据范围）、DEC-PERM-02（敏感字段）
3. 哪些动作需要审批，按什么金额/数量分级，谁能撤回、作废或强制处理。→ docs/20 DEC-PERM-03；导出权与管理员明文权 → DEC-PERM-04
4. 离职交接的责任人、完成时限和可例外条件。（不在 docs/20 本轮决策题范围；离职交接状态机为备选开发工作包，见 `19-开发进度与交接.md` 第 7 节）
5. 是否需要企业微信扫码登录/单点登录及高权限二次验证。（不在 docs/20 本轮决策题范围，依赖 D 节平台权限确认）

## D. 外部平台

1. 企业微信主体、应用、客户联系 API 权限和现有 userid/external_userid 导出能力。
2. 小程序主体、member_id/OpenID/UnionID 获取能力、员工二维码/邀请码方案。
3. 短视频和直播平台名称、账号归属、开放平台权限、指标和历史数据范围。
4. 各平台数据保存、员工/客户授权和合规要求。
5. API 不可用时是否允许人工导入，哪些字段只能系统同步。

## E. 技术与上线

1. 生产部署在公司机房、国内云还是混合环境；域名、HTTPS、备案和远程访问要求。
2. 门店网络质量、是否需要 VPN、是否存在断网继续开单的硬性需求。
3. 扫码枪、标签打印机、小票打印机、摄像头、串口设备型号与驱动。
4. 谁负责系统管理员、数据库备份、故障响应、员工培训和权限审批。
5. 允许的停机切换窗口、旧系统并行/只读期限和回退条件。

## 建议的确认方式

安排 2 次各 90 分钟的业务工作坊：第一次只走销售、收款、库存和退换货真实案例；第二次走采购、调拨、权限、迁移和异常。会后用 10 个真实单据样本验证结论，并由销售、库管、财务、店长共同签字。**工作坊现场使用 [`20-业务签字决策清单.md`](20-业务签字决策清单.md) 逐题勾选，议程见该文第 3 节。**
