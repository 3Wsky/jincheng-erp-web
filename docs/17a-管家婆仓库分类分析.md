## 4. 关键观察

1. **仓库编号不完整**：多数仓库没有编号（空），仅有总库（01）、米泉分销（02）、鸿翔一店（04）、米泉北路店（05）、联通店（07）、鸿翔荣耀厅（09）带编号。编号不能作为仓库唯一键。
2. **仓库全名是稳定标识**：以「仓库全名」作为管家婆侧的自然键，后续映射到 ERP `Warehouse`。
3. **两大类口径**：
   - 门店仓库：以「店/厅/营业厅/合作店」命名，另有总库（公司总仓，1,924 台，占全量 31%）、售后类（潘国杰售后 312 台、售后 3 台）
   - 个人分销仓库：以员工/业务员姓名命名（支文香、杨菲、刘玉昆、高磊等），管家婆把个人名下库存登记为独立"仓库"
4. **全量 vs 过滤差异**：8-10 过滤版仅 2,360 条；8-11 全量 6,165 条，总库从 340 台增至 1,924 台，且新增「潘国杰售后」（312 台）等重要分类。
5. **成本单价列显示异常**：多行为 `-2457.63` 或 `***`，说明导出文件对成本字段做了脱敏或异常标记，不能作为真实成本来源。

## 6. ERP 仓库映射建议（待签字）

1. `Warehouse.code` 使用仓库全名（或规范化拼音缩写），`Warehouse.sourceSystem="GRASP"` + `SkuExternalIdentity` 记录管家婆原始仓库名，避免员工手工改名导致对账丢失。
2. `Warehouse.type` 映射：门店仓库 → `STORE`（总库 → `COMPANY`）；个人分销仓库 → `PERSONAL`（关联 `ownerEmployeeId` 与 `storeId`）。
3. PERSONAL 仓库关联员工档案：一个员工名下可合并多个管家婆"个人仓"记录（如支文玉/支文玉2）。
4. 迁移期初库存单据按「仓库全名 + 序列号」逐台导入，数量=1，写入 `InventoryMovement`（PURCHASE_RECEIPT 期初类型待确认）。
5. 暂不冻结销售结构；本文件只影响 `Warehouse` 主档与库存期初，不改变销售单模型。
