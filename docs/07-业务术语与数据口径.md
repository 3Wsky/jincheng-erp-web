# 锦程 ERP Web 业务术语与数据口径

## 1. 使用原则

系统必须区分“原始事实、业务决定、派生指标”：原始事实来自单据或外部平台；业务决定由审批或异常处理产生；派生指标必须能下钻到事实来源。任何暂未确认的公式不得以硬编码方式进入生产。

## 2. 核心术语

| 术语 | 定义 | 当前状态 |
|---|---|---|
| 商品 Product | 共同品牌、品类和型号的产品主档 | 已确认 |
| SKU | 商品的颜色、容量、版本等可销售规格 | 已确认 |
| 序列号商品 | 按 IMEI/SN 逐台追踪库存、成本和责任人的商品 | 已确认 |
| 数量商品 | 按 SKU × 仓库记录数量和成本的商品 | 已确认 |
| 序列号档案 SerialItem | 一台设备在公司内部的唯一身份和完整时间线 | 已确认 |
| 公共库 | 公司或门店共同管理的仓库 | 已确认 |
| 个人库 | 指定员工承担实物责任的逻辑仓库 | 已确认 |
| 在途库存 | 已从来源库发出、目标方尚未确认接收的库存 | 已确认 |
| 可售库存 | 状态允许销售且未被其他有效单据锁定的库存 | 暂定，需确认锁定时点 |
| 库存流水 | 由生效业务单据产生、不可直接编辑的增减记录 | 已确认 |
| 业务资金流水 | 采购付款、销售收款、退款、费用等经营事实，不等同会计总账 | 已确认 |
| 已付未到 | 已确认采购付款对应金额减去已确认到货对应金额 | 暂定，需确认分摊算法 |
| 客户主档 | 公司内部统一 `customer_id` 及其外部身份映射 | 已确认 |
| 有效回访 | 满足实名客户、员工、时间和结果规则的回访事实 | 暂定 |
| 业务待办 | 能推进具体业务状态的待处理事项，不是普通消息 | 已确认 |
| 冲销 | 以相反业务记录抵消已生效历史，不覆盖原记录 | 已确认 |

## 3. 标识符规则

- 内部主键统一使用不可变 UUID；展示编号独立生成，不把手机号、IMEI 或外部 ID 作为主键。
- `employee_id`、`store_id`、`product_id`、`sku_id`、`customer_id` 在内部全局唯一。
- IMEI1、IMEI2、SN 分字段保存；空值允许，但非空值在公司范围内唯一。
- 外部数据保留 `source_system`、`source_id`、同步批次和原始载荷摘要。
- 单据编号应包含业务类型、日期和序列，但编号生成规则需在阶段 0 定稿。

## 4. 数量与金额口径

| 指标 | 暂定公式 | 必须确认的问题 |
|---|---|---|
| 账面库存 | 所有已生效库存流水数量之和 | 是否允许负库存 |
| 可售库存 | 账面库存 − 锁定 − 在途不可售 − 售后/异常不可售 | 销售锁定和释放时点 |
| 责任库存 | 当前责任人为该员工且未完成转交/归还的库存 | 样机、借出是否计入 |
| 采购金额 | 采购明细确认数量 × 含税单价之和 | 税率、运费和返利处理 |
| 已付金额 | 已确认且未冲销的采购付款之和 | 预付款和供应商余额 |
| 已到金额 | 已确认收货数量按采购成本分摊 | 费用分摊和超收 |
| 销售额 | 已生效销售明细金额 − 已生效退货金额 | 优惠券、以旧换新和补差价 |
| 实收金额 | 已确认收款 − 已确认退款 | 分期、赊销和手续费 |
| 序列号成本 | 对应单机确认入库成本 | 返利和后补费用 |
| 数量商品成本 | 暂按移动加权平均 | 财务最终确认 |
| 毛利 | 不含税销售净额 − 销售成本 − 指定分摊费用 | 税、平台费和员工提成是否扣除 |
| 业绩 | 按已生效销售单分配，退货按原分配冲回 | 多人比例、跨月退货规则 |

## 5. 时间、精度和枚举

- 数据库存储带时区时间，统一使用 `Asia/Shanghai` 展示和按营业日汇总。
- 金额使用 `Decimal(18,2)`；比例和成本中间计算建议保留 4～6 位，最终展示按财务规则舍入。
- 数量商品当前按整数设计；若存在散装或小数单位，必须在建表前确认。
- 状态使用稳定英文枚举，界面显示中文；禁止把自由文本作为核心状态。
- 已生效单据禁止修改关键金额和数量，只能变更、作废或冲销。

## 6. 阶段 0 必须签字的口径

1. 销售开单、锁货、扫码、收款、扣库存和完成的先后关系。
2. 退换货、退款、补差价、跨月退货和业绩冲回。
3. 含税/未税售价、成本、返利、运费、平台手续费及毛利公式。
4. 分期、赊销、优惠券、以旧换新和批发业务的资金表达。
5. 可售、锁定、个人库、样机、借出、售后和异常库存边界。
6. 日结边界、跨天营业和报表时区。
