## 3. 状态标签

| 标签 | 含义 | 能否作为开发定稿 |
|---|---|---|
| `待确认` | 缺少真实业务结论或样本 | 否 |
| `暂定` | 可用于原型或接口草案，后续可能调整 | 仅限可逆工作 |
| `已确认` | 业务负责人书面确认 | 是 |
| `已实现` | 代码和迁移已完成 | 仍需测试 |
| `已验收` | 测试、对账和业务签字完成 | 是 |

任何文档未标注时，默认状态为“暂定”。销售、库存、资金、成本、权限和业绩相关结论必须有负责人及确认日期。

## 4. 文档更新规则

- 需求使用 `REQ-*`，验收使用 `AC-*`，测试使用 `TC-*`，接口使用 `API-*`，决策使用 `ADR-*` 编号。
- 状态机、金额计算和权限发生变化时，同一提交内更新对应文档、接口契约、迁移影响和测试用例。
- 不删除已经执行过的业务事实；废弃规则需记录生效日期、替代规则和历史数据处理方式。
- 新增外部集成时必须记录平台主体、授权范围、字段来源、限流、重试、对账和降级方案。
- 每两周检查需求追踪矩阵，确保需求、代码、测试与验收状态一致。

## 5. 换机交接清单

- 携带整个仓库，而不只是 `docs/`；必须包含隐藏的 `.git`、`apps/`、`packages/`、`infra/` 和锁文件。
- 不提交或复制真实 `.env`、数据库备份、客户资料、平台密钥和未脱敏导出。
- 新电脑安装 Node.js 24、pnpm 11、Git 和 Docker，再按根目录 `README.md` 启动。
- 首次开发前运行 `pnpm install`、`pnpm db:validate`、`pnpm db:generate`、`pnpm build`、`pnpm lint`、`pnpm typecheck`、`pnpm test`。
