# 锦程 ERP Web 角色权限矩阵

## 1. 状态与原则

本矩阵是阶段 0 的签字底稿。最终权限 = Role × DataScope × Action × Field × Approval；兼岗员工可以多角色，但权限叠加规则和高风险冲突必须书面确认。

**2026-08-12 业务确认（已实现）**：核心五岗为**管理员、财务、出纳、库管、人事**（店长/销售/老板/运营角色保留供门店端上线使用）。财务与出纳分设，执行**钱账分离**：财务管账与单据审核（`procurement:write`、`finance:write`），出纳执行付款（`procurement:pay`），两者不互相兼有；采购付款接口仅 `procurement:pay` 可调（实测：出纳可付款不可审批、财务可审批不可付款）。DataScope/Field/Approval 三维仍为“暂定”待签字。

已实现的权限码映射（`packages/database/scripts/seed.ts` 为权威来源，**22 个权限码**）：出纳 = `catalog:read + inventory:read + procurement:read + procurement:pay + finance:read + report:read`；人事 = `organization:read/write + account:write + role:read + report:read`；系统管理员 = 全部权限（含 `role:write`）。**2026-08-15**：`/admin/roles` 从只读矩阵升级为管理台——9 个内置角色锁定（seed 权威，防误改钱账分离），管理员可创建自定义角色并勾选权限；自定义角色禁止授予 `role:write`；人事可开账号但不能授予「系统管理员」；系统始终保留至少一个可用管理员。DataScope/Field/Approval 三维仍待签字。

## 3. 数据范围

| 范围 | 定义 | 示例 |
|---|---|---|
| `SELF` | 仅本人责任或归属数据 | 个人库存、本人客户、本人业绩 |
| `STORE` | 当前所属门店 | 店长查看本店销售和员工 |
| `SELECTED_STORES` | 明确授权的多个门店 | 区域库管、区域运营 |
| `REGION` | 指定区域下所有门店 | 区域负责人 |
| `ORGANIZATION` | 全公司 | 老板、特定财务角色 |

服务端必须从账号上下文解析范围，禁止信任客户端传入的 `store_id` 扩权。

## 4. 敏感字段策略

| 字段类别 | 默认策略 | 可见角色 |
|---|---|---|
| 单机/库存成本 | 隐藏或只读 | 财务、老板；店长/库管待确认 |
| 毛利与毛利率 | 隐藏 | 财务、老板；店长仅本店待确认 |
| 客户完整手机号 | 中间位脱敏 | 归属销售、授权店长；其他按需 |
| 供应商账户 | 隐藏 | 财务及授权采购审批人 |
| 支付账户/流水号 | 脱敏 | 财务、老板 |
| 员工身份证/银行卡 | 加密并默认隐藏 | 指定人事角色 |
| 外部平台令牌 | 永不在业务界面展示 | 系统密钥管理服务 |

## 5. 审批与高风险操作

- 采购下单、付款、销售折扣、退款、库存调整、报损、盘盈盘亏按金额或数量分级。
- 创建人不得审批本人高风险单据；紧急强制处理必须二次确认并产生独立审计事件。
- 导出客户、财务或全公司数据需要独立权限，不能因能查看列表就自动获得导出权。
- 系统管理员负责技术配置，不默认拥有客户、成本、毛利和财务明文读取权。

## 6. 权限验收

每个角色至少建立：正常访问、跨店对象 ID、修改 URL、批量接口、导出、搜索、报表下钻、字段脱敏和审批额度九类反向测试。任何越权读取或写入均为 P0 缺陷。
