# 锦程 ERP Web 项目章程

## 1. 立项目的

建立一套面向手机数码/3C、多门店、多员工的公司内部 ERP，先以响应式网站替换旧管家婆中最容易卡死、依赖微信群和 Excel、且关键能力缺失的业务环节。后续 PC 桌面端、员工 APP 和小程序不重复建设业务后台，而是复用统一 API 与主数据。

## 2. 成功定义

系统上线后，管理者和员工应能稳定回答并处理以下问题：

1. 某型号或某个 IMEI/SN 在哪里、什么状态、由谁负责。
2. 采购付了多少、到货多少、还有多少已付未到。
3. 调拨当前到哪一步，谁还未确认，异常如何闭环。
4. 销售单如何扣库存、收款、核算毛利并归属员工和客户。
5. 员工本人的销售、个人库存、视频、直播、回访和待办情况。
6. 客户来源、历史购买、跟进记录和下次联系时间。
7. 不同角色只能看到、操作和审批自己被授权的范围。
8. 日、周、月经营结果可自动形成，关键历史可追溯。

## 3. 网站先行策略

- 电脑端负责复杂表格、批量导入、审核、报表与配置。
- 手机浏览器/PWA 负责扫码、找货、收货确认、调拨确认、回访和个人待办。
- 只有当离线、深度硬件、推送或应用商店分发成为真实瓶颈时，再开发原生 APP。
- PC 桌面端优先考虑对网站端做轻量桌面封装，只有打印、串口、专用扫码枪等能力不足时再做原生模块。
- 小程序只开放面向会员或客户的必要能力，内部管理权限不直接暴露。

## 4. 首期范围

### 必须先完成的经营主链路

- 组织、门店、员工、账号、角色、数据范围、字段权限、审批额度。
- 商品、SKU、序列号商品、数量商品、仓库与个人责任库。
- 全局查货、库存流水、盘点、异常和完整审计。
- 调拨申请、锁定、出库、在途、扫码接收、差异处理。
- 采购、付款、收货、部分到货、已付未到差异。
- 销售、收款、扣库存、退换货、客户和员工业绩。
- 统一待办、基础经营报表和上线运维能力。

### 第二批能力

- 企业微信、小程序会员、短视频与直播平台接入。
- 客户来源归因、员工 360 经营档案、自动日周月报。
- 更复杂的售后、活动、提成和经营分析。

### 首期明确不做重

- 完整总账、会计凭证、资产负债表。
- 复杂工资系统、大型 OA、与当前业务无关的重型 CRM。
- 微服务、Kubernetes、多租户 SaaS、数据湖等过度架构。

## 5. 当前事实与限制

- 现有资料仅包含两份产品蓝图，没有旧管家婆数据库、接口文档、导出样例或源码。
- 销售单来源、扣库存与收款流程仍是最高优先级未决项。
- 项目进度估算暂按 30 门店以内、500 员工以内、100 并发用户的试点规模规划；获得真实数据后必须校正。
- 外部平台接入范围以平台实际 API 权限、合同、合规要求和可获取字段为准。

## 6. 治理与变更规则

- 原始需求作为母版，不无故删除已确认要求；变更必须说明原因、影响和验收调整。
- 每个需求要有唯一编号、负责人、实现版本、测试用例和验收结果。
- 关键状态机、成本口径、业绩口径和权限矩阵需要业务负责人书面确认。
- 每两周演示可运行增量，不到最后阶段才集中验收。
